# Hypnotic Rings — документация

Это оглавление и единственный документ, который ссылается на остальные. Если
документ не достижим отсюда — он потерян.

Всё, что проект документирует, лежит под этой папкой. В корне документов нет
(кроме `CLAUDE.md` — он правила для агента, а не документация проекта).

| Где | Что |
|---|---|
| `design/` | исходные документы, ровно как переданы — не редактируются никогда |
| `GAME_DESIGN_SPEC.md` | рабочая копия спецификации, главный источник чисел и поведения |
| `CONTRACT.md` | что спецификация означает на практике: механика, строки, архитектура, закрытые пробелы |
| `DECISIONS.md` | необратимые пять и журнал всех принятых решений |
| `PROGRESS.md` | чек-лист фаз — **здесь смотрят, где остановились** |
| `BACKLOG.md` | что сознательно не делается в v1 |
| `publishing/` | пакет для отправки: тексты, арт, политика, ответы Console |
| `publishing/README.md` | **отсюда начинают с вопросом «можно ли уже отправлять»** |

| `benchmarks/` | замеры, на которые ссылаются решения: способ сжатия колец и шаг физики (фаза 1) |

Отчёты появляются по мере прохождения фаз: `BALANCE_REPORT.md` (фаза 4),
`VISUAL_REVIEW.md` (фазы 5 и 6), `PERF_REPORT.md` (фаза 9),
`RELEASE_HANDOFF.md` (фаза 12). `BLOCKERS.md` появляется только если работа
упёрлась во внешний блокер.

## Где проект сейчас

Фаза 6 закрыта. Игра проходится целиком с клавиатуры тестов: меню → забег →
конец игры → повтор → домой, с темами, настройками, сохранением и двумя
языками. Собранная сцена запускается с Boot и доходит до меню.

Чего ещё нет: звука (фаза 7), полировки ощущений (фаза 8), замеров
производительности на устройстве (фаза 9) и собранного `.aab` (фаза 10).
Отправлять пока нечего — артефакта не существует. Подробности в `PROGRESS.md`,
причины принятых решений — в `DECISIONS.md`.

| `tools/contact_sheet.py` | сводит 30 кадров экранов в одно изображение |
| `python3 docs/publishing/check-listing.py` | пакет для стора против лимитов |

## Соглашения

- Исходники в `design/` только читаются. Трактовка — в `CONTRACT.md`, чтобы
  потом можно было сравнить одно с другим, когда правило оспорят.
- Текст листинга существует ровно в одном месте — `publishing/store-listing.md`,
  внутри кодовых блоков. Всё остальное на него ссылается или сверяется с ним
  программно. Перенабранный текст теряет абзацы, и это не ловится ничем, кроме
  diff.
- Числа об артефакте читаются из артефакта. Цифра из лога сборки — догадка и в
  этих файлах ей не место.
- Механика описана один раз, в `CONTRACT.md` §2. `MECHANIC.md` плана — это
  указатель туда, а не вторая копия.
